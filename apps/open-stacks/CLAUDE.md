# Open Stacks Wiki

Astro/Starlight research wiki on **exploring the world's literature cheaply and well**: what is free and legal, cheap and institutional access routes, discovery and AI research tools, reading environments (e-ink to VR), the legal constraints on building tools, a reference architecture for a personal "catalog of everything", and a gallery of interface mockups and prototypes. Part of the CAIRN pnpm monorepo; sibling to `reasoning-processes` and `evaluation-engineering`.

## Commands

```bash
pnpm dev                # wrap prototypes, then start the dev server at localhost:4321
pnpm build              # generate llms files, wrap prototypes, build the site
pnpm build:prototypes   # only regenerate public/prototypes/*.html
pnpm fetch:data         # re-fetch the prototypes' datasets from open APIs (slow; polite rate limits)
pnpm lint
```

Run from this directory, or from the repo root with `pnpm --filter open-stacks <cmd>`.

## Prototypes

Each file in `prototypes/` is a page *fragment* (its own `<title>`, `<style>`, markup and scripts; no `<html>`, `<head>` or `<body>`), so the same file publishes unchanged as a Claude artifact. `scripts/build-prototypes.mjs` wraps each one in a document skeleton for the static wiki. Rules for prototype code:

- Load data by relative URL (`fetch('data/catalog.json')`). No runtime calls to other hosts: the artifact viewer blocks them.
- Libraries only from cdnjs / jsDelivr / unpkg, pinned to exact versions.
- On-the-fly generation goes through the artifact runtime's `sample` capability (`await window.claude?.use?.('sample')`). It is `null` or absent on the static wiki, so every generated feature needs a precomputed fallback, and generated text is labeled as AI-generated.
- Light and dark themes through CSS tokens; usable at 390px width.

## Data

`public/prototypes/data/` holds real metadata: `catalog.json` (Open Library, CC0), `gutenberg.json` (Project Gutenberg catalog), `papers.json` (arXiv metadata, CC0), `lcc-outline.json` (LC Classification Outline, public domain). Regenerate with the scripts in `scripts/`; each documents its source and fields.

## Sidebar

The sidebar in `astro.config.mjs` is explicit and numbered. To add a chapter: create the page, add a `{ label, slug }` entry, and add its row to the table on `src/content/docs/index.mdx`. `public/llms.txt` and `public/llms-full.txt` are generated from the sidebar at build time; don't edit them by hand.

## Content Conventions

- **Frontmatter**: every page needs `title` and `description`.
- **Status line**: each chapter opens with an italic status line giving the date and what is and isn't verified.
- **Escape `$`**: write `\$100`, not `$100` (KaTeX).
- **Dates and prices**: say "as of October 2026" (or the source's date) for any price, catalog size or product status; these go stale fastest.
- **Confidence**: mark uncertain claims inline, e.g. "[~70%]"; separate what a primary source says from inference.
- **Citations**: link primary sources inline. The dossiers in `research/` hold the longer source lists and verification notes.
- **No personal details** about any individual reader; write for researchers in general (Bay Area examples are examples).

## Content Style

- Analytical, evidence-based tone; precise numbers; no hype.
- Pages are working notes, not settled positions; each chapter ends with Open Questions.
- Comparison tables for options (price, coverage, access requirements, status).
- Keep pages focused on one topic; link between related pages.
