# Stacks Browser architecture

How the pieces fit, for anyone adding a feature. The README covers running and using it.

## Server (`server.mjs`, `server/`)

- `server/config.mjs` exports `HERE`, `PORT` (`--port N` or `STACKS_PORT`), `CACHE` (`STACKS_CACHE`, default `~/.cache/open-stacks`), `MODEL` (`STACKS_MODEL`), `UA` and `hasKey()`.
- `server/cache.mjs` is the disk cache for open sources: `allowed(url)`, `cached(url)`, `ensure(url)` (fetch once into the cache), `meta(url)`, `read(url)`, `paths(url)`, `key(str)` (sha1), `enqueue(urls, pri, group)` (the prefetch queue) and `stats`. `onDead(fn)` lets `server/rescue.mjs` replace a document that fails for good (404, 410, 451, a vanished host) or now serves a placeholder page with its Internet Archive copy, inside `ensure`, so every caller gets it.
- `server/routes/*.mjs` load in name order. Each exports `default function (app)`; `app` has:
  - `route(method, pathOrRegExp, async (req, res, url, match) => {})`, where method is `'GET'`, `'POST'` or `'*'`;
  - `status(() => ({...}))` to add fields to `GET /status`;
  - `onStart(fn)` to run after the server starts listening;
  - helpers `json(res, obj, code)`, `send(res, code, body, type)` and `body(req)` (parsed JSON);
  - `cache`, `CACHE`, `HERE`, `MODEL`, `UA` and `hasKey`.
- `GET /ready?ids=` (`server/routes/13-ready.mjs`): per item, `[first, frac]`: whether the spread it opens at is on disk, and the share of it on disk (books: their pages, sampled). The Library dims items not fetched yet and shows a percentage for books partly fetched.
- Your own folders (`server/local.mjs`, `server/routes/17-local.mjs`; section below): the `local` lane, files read in place. `app.local` (`ready(id)`, `has(url)`) lets `/ready` report them on disk (or still in iCloud) and `POST /cached` count them; `profile.mjs` and `augment.mjs` look them up through `registerItems(fn)`.
- The warm-up (`server/routes/60-warm.mjs`) fetches the opening spread of every item, in the order you will see them: first the next 80 items of the stack you are walking (`ahead`, sent by `features/telemetry.js` when the stack changes or you move 15 items on), then every lane in its own sort. `STACKS_WARM_MB` (default 3000) caps it.
- Static files come from `ui/`. `/corpus.json` and `/enrich.json` (optional) come from the browser folder. `/features.json` lists `ui/js/features/*.js` and `ui/features/*.css`.

## Client (`ui/js/`)

`main.js` imports the core modules, then every feature module listed in `/features.json`, then calls `boot()`. A feature is one file in `ui/js/features/` plus, optionally, one stylesheet in `ui/features/`. Prefer adding a feature over editing core files.

### Hooks (`util.js`)

- `on(name, fn)` and `emit(name, detail)` drive an event bus. The events are:
  - `item:shown {i, it}`;
  - `item:skim {i, it}`: a step of hold-to-skim (`riffle.js`: holding `j`/`k` steps through the stack showing each item's title and, when at hand, first page); not a visit, nothing loads, and only the item released on gets `item:shown`;
  - `spread:rendered {i, it, s, els, doc, flow?}`; for rasters, `els[j]._pnl` is the panel and `els[j].dataset.k` the page;
  - `summary:updated {id, summary}`;
  - `nav {type, i, it, ...}`; types: `item`, `turn`, `page`, `random`, `zoom`, `back`;
  - `nav:before {label, i, pos, s, hist, zoom, at?, hat?, order?, aff?, saved?, lane?, stk}`, where you were just before a move or judgment (`at` and `hat`: for a flow document on screen, `flow.js` `colPos` of `s` and of each column in `hist`, so Back returns to the same text after a reflow: `features/back.js` answers the item's first `reopeners` call with `posCol(at)` and maps `hist` the same way; `features/back.js` keeps them for Back; `stk` is the stack you were in, added by `stack.js`, and Back hands the snapshot back as `nav {type: 'back', undone, snap}` so the stack is restored too);
  - `stack:changed {stack}` (`stack.js`: after a sort change, a stay-in, leaving, `goTo` and a lane switch) and `stack:show {stack}` (the header crumb was clicked: `features/library.js` shows the stack); `library:show {lane, path}` (`features/headpop.js`: the Library opens on that lane or folder without changing the stack, and sets `shown`; in a sort other than By topic the Library is a list and `shown` stays false);
  - `gesture:step {axis, dir, device, fresh}` and `gesture:pinch {dir, x, y}` (`gesture.js`); a step listener sets `stop` to end the gesture;
  - `view:changed {view}`;
  - `header:changed {head, focus, peek}` (`header.js`: the header's layout changed, or Focus's header was shown or hidden; the stage has been laid out again when the layout changed);
  - `panel:painted`, `status`, `boot` and `flow:jump`;
  - `memory:updated {id}` (`features/memory.js`, which also exports `progressOf(id)` → `{seen, n, frac, far, at, done, ms, visits, …}` or null);
  - `item:error {i, it, msg}` (`feed.js` `showError`: the item could not open; `features/flag.js` reports it to `POST /jobs/report`);
  - `corpus:changed {added, changed}` (`corpus.js` `mergeItems`: item indexes appended or updated in place, e.g. a file added to your folder; `state.js` drops its sort caches, `features/library.js` rebuilds its tree, `search.js` its index);
  - `learn:updated {at, on}` and `learn:new {n}` (`features/learn.js`: a new learned profile arrived; the number of new finds changed);
  - `overview {open}` (`features/overview.js`, the page grid over the stage, key `O`; it also exports `openOv()`, `closeOv(k?)` and `ovTimes`, and keeps its own pdf.js document for thumbnails).
- `registerKey(keys, fn, {help: [label, text], view: 'feed' | null, order, repeat})`. The keys overlay is generated from these help entries. Key auto-repeat is ignored unless `repeat: true`.
- `registerStepper(fn, order)`: `fn(dir, e)` returns true when it handled an Advance (`dir` 1) or Back (`dir` -1) step. `features/back.js` answers Back from its undo stack; otherwise Advance turns the page and then moves to the next item, and Back turns back.
- `registerSection({id, title, order, render(it, i) → Node | null})` adds a side-panel section, rendered as `#sec-<id>`. Built-in orders: why 10, summary 20, outline 30, note 40, related 50, today 60.
- `registerView(name, {label, key, order, roots: () => [elements], show(), hide()})` adds a top-level view. Create its root element inside `#main`. Feed and Wall are views too.
- Learned ranking (`state.js`; `features/learn.js` registers both): `registerScoreTerm(fn)`, `fn(i, it)` → a number added to `score(i)`; with none registered, `score()` keeps the old `state.aff` terms (lane affinity clamped to ±1). `registerLaneFactor(fn)`, `fn(lane)` → a factor on the lane's share of All's round-robin (weight `max(0.1, LANE_WEIGHTS[l]·factor)`); with none, `1 + 0.5·clamp(aff.lane, ±1)`. `baseScore(i)` is the ranking with nothing learned: noise·0.9 + 0.8·q + 0.8·(rel − 0.5) + 0.35 for PDFs. The arrays `scoreTerms` and `laneFactors` are exported, so a feature can splice its function out (learning off) and call `buildOrder(true)`. `learn()`, `state.aff` and `back.js` stay as they were: they feed the fallback and Back's snapshot.
- `registerWhyLine(fn)` (`util.js`): `fn(it, i)` → a Node or null, appended to the panel's "Why this" section after the why line. While any is registered, the section drops its "you liked …" line.
- `registerTextSource(async ({i, it}) → {words, start} | null)` (`text.js`). A word is `{text, page, range?, el?}`.
- `state.stepHook(d)`: a mode that owns the wheel answers a `gesture:step` first (`nav.js` asks it; true = handled). Read-aloud uses it to move the voice a sentence a notch.
- Read-aloud (`features/readaloud.js`) is a mode: while it is on (`html.ra-on`), a capture-phase key handler takes ← → h l Space ↑ ↓ Esc ahead of `chrome.js` and `riffle.js` (not from the library list or the Settings sheet; Esc closes an open sheet first), a click on a word reads from it, a jump (`nav` `page` or `random`) takes the voice along while a turn only holds the follow for 5 s, it never follows from inside a `spread:rendered` handler (that runs within `showFeed()`, before the turn's `nav` event), and the player sits in `#stage` under `#spread` (the pages shrink to make room). It exports `registerEngine({id, label, kind: 'events' | 'audio', sizes, voices(), available(), speak(...)})` for more voices (an `audio` engine returns `{buf | blob | url, wordTimes?}` for a passage), `readAloud` (`start(opt)`, `stop()`, `on`, `playing`), `readAloudPrefs`, `setReadRate` and `setReadVoice('engine:voice')`.

### Units

- **Raster items (scan, pdf):** page `k` is 0-based. `state.start` holds the first page shown.
- **Flow items:** `state.start` holds a *column*. Stable pages (`data-vp` on blocks, about 280 words each) are what summaries cite, the strip shows and `goPage(k)` takes.

### Images and dead links (`features/rescue.js`, `server/rescue.mjs`, `server/routes/14-media.mjs`)

Every image in a flow document loads through `GET /img?u=` (a `flowFilters` hook rewrites `src` and `srcset`; the original stays in `data-orig`). The server fetches it once into the disk cache and checks it: HTTP errors, a web page instead of an image, and placeholders (imgur's removed.png and its region block, found by a canary at startup; Flickr, Photobucket and Tinypic placeholders; 1x1 pixels; identical bytes behind different ids on an image host; images the reader flags) count as broken. A broken image is looked for in the post's own other copies (srcset), mirrors (https, i.imgur.com forms, Wikimedia originals, Substack's proxy) and the Wayback Machine (availability API, then CDX; the raw `id_` snapshot), and served with `X-Stacks-Via`. In the reader an image of unknown fate reserves a small box, an unavailable one becomes a one-line chip (alt text, links to the original and the archive, "fix…" to paste a copy), and a rescued one says where it came from on hover. A scavenger retries what is still broken every few hours (`POST /rescue/run`); with `STACKS_RESCUE_AI=1` it also asks Claude, with web search, for other copies, checks each before use, and spends from the summaries' daily budget. State and a log of rescues: `CACHE/rescue.json`; counts in `/status` (`rescue`).

## Your own folders (the Local lane)

Files from folders on this machine, read in place: nothing is copied into the repository or sent anywhere, and the index and converted output live under `CACHE/local/` (`meta.json`, `settings.json`, `docs/`).

- Folders: Settings › Local folders (`CACHE/local/settings.json`; one per line, full paths, none inside another), else `STACKS_LOCAL_DIRS` (':' or new lines; `~` expanded), else `~/Library/Mobile Documents/com~apple~CloudDocs/Recent Things to Read` when it exists. `STACKS_LOCAL_ORDER=newest` changes the default order in a folder (name, natural: 2 before 10).
- `server/local.mjs` (pure parts tested on their own): `LocalIndex` walks the folders (dotfiles, `.DS_Store`, empty files, partial downloads, symlinks, bundles and `__MACOSX` left out; 20,000 files and 14 levels at most), groups two or more pictures or sound files in a folder into one gallery or playlist item (a folder of nothing else stands in the folder above), makes a *bundle* (`bundleOf`: a subfolder named `*.stack` or holding `index.md`/`index.html` at its top, never a configured folder itself) one item in the folder above without walking into it (kind `bundle`, id from `<path>/#bundle`, `ext: 'bundle'`; its text is the index file, index.md first, else a `.stack` folder's first Markdown or HTML file; `bundleMeta` reads front matter with lists, `<title>`, `<meta name="author|date|dcterms.date|description|keywords">`, `<link rel="canonical">`, then `stack.json` on top, into `a`, `y`, `d`, `page` (the source), `ab`, `tags`; `cover.*` or stack.json's `cover` becomes `cover`, a `/local/rel` URL the wall shows as a photo card), drops a zip beside its unpacked folder, and reads metadata in the background (3 at a time; `pdfinfo`, else `mdls` on a Mac, else `sniffPdf`; the EPUB package, Word's `docProps/core.xml`, Markdown front matter or first heading, `<title>`, `Title:`/`Author:` lines), cached by path, size and mtime. Items: id `local:` + 20 hex digits of sha1(`<folder name>/<path inside>`) (a `.X.icloud` placeholder has the id of X, so it survives the download), `lane: 'local'`, `path` ([folder name, …subfolders]), `ord` (depth first, a folder's files before its subfolders), `kind` (`pdf` and `text` at `/local/file/<id>?v=`, everything else `html` at `/local/doc/<id>?v=`; `v` changes with the file), `why` ("Your folder › Papers", plus the `brctl download` fix for iCloud), `src: 'local'`, `private` (true unless Settings makes AI automatic), `size`, `ext`, `count`, `cloud` (`stub`: an `.icloud` placeholder; `evicted`: a macOS 14+ dataless file, no blocks on disk, never read for metadata). ## Server-side page rendering

PDF pages rendered on the server by a native engine, on all cores but one, ahead of the reader, so a PDF page arrives as a JPEG to decode instead of a pdf.js render on the main thread. First version of `docs/performance/prerender.md` (its Status section says what is built and what is not). Everything works the same without an engine: the browser draws with pdf.js as before.

- `server/pdfnative.mjs`: the engines, tried in order from `STACKS_RENDER_ENGINE` (`quartz` | `poppler` | `mupdf` | `none`, alias `off`; unset: from the top). `quartz` is `server/native/stacks-render.swift` (macOS only): built once in the background with `xcrun swiftc -O` into `CACHE/render/bin/stacks-render-<hash of source and compiler>` when `xcode-select -p` and `xcrun --find swiftc` succeed (never `swiftc` blindly: that opens the install dialog), a persistent helper per pool slot speaking JSON lines (`LineWorker`); a failed build leaves `CACHE/render/bin/build.log` and is not retried until the source or the compiler changes. `poppler` is `pdftoppm -hide-annotations -cropbox -jpeg -jpegopt quality=80 -r … -x 0 -y 0 -W … -H …` per page (else `pdftocairo`), with `pdfinfo` for page sizes. `mupdf` is `mutool run server/native/mu-render.js` per page (its `saveAsJPEG`: `mutool draw` writes no JPEG in 1.23). An engine is used only after `selfTest()` passes on the geometry PDF of the spec's Appendix C (`geometryPdf()`: page sizes through crop boxes and rotations, three renders at the expected size); a page an engine fails is tried on the next, and an engine that fails five pages in a row that the next one renders goes to the back. Background renders run at `nice` 5 (near) or 10 (ahead; `taskpolicy -c utility` on a Mac). Also `sizeClass`, `fitPage`, `jpegSize`, `pdfinfo`, `findEngines`, `renderTo`.
- Geometry: a page is its crop box clipped to the media box with `/Rotate` applied, as pdf.js shows it, drawn whole to fit `0.85·w × w` px at size class `w` (1400, 1800 or 2200: the client's `RENDER_H` rounded up), the box `render.js` draws pdf.js pages into, so `srcW × srcH` and the crop fractions match a pdf.js render and the text layer, highlights and figure peek line up. Annotations are not drawn (hyperref's coloured link boxes; pdf.js's canvas does not draw them either).
- `server/render.mjs` `createService({dir, cache, workers, max, prefer})`: the pool, `W = STACKS_RENDER_WORKERS` (default cores − 1) slots, and three lanes: `fg` (a request is waiting; may use every slot), `near` (the next two spreads and the one before of the open document, the first spreads of the next three PDFs) and `ahead` (pages 3 spreads to 40 pages on, 20 back, the next PDFs' first spreads, then the rest of the open document, at most 600 pages); `near` and `ahead` together hold at most `max(1, W − 1)` slots (`laneCaps`), so a foreground page never waits behind background work. Inside a lane: priority, then the newest plan, then first come. A hint replaces the plan: queued background jobs it no longer names are dropped (running ones finish; a job a request waits for stays). A job whose PDF is not on disk waits without a slot (`near`: `cache.ensure(u, {fg: false})`; `ahead`: until the prefetch queue brings it, checked every 2 s). A foreground job nobody waits for any more drops to `near`. Pages: `CACHE/render/<sha1(url)>/<k>_<w>.jpg` beside `info.json` (`{url, size, n, pages: [{w, h}]}`, points; stale when the cached PDF's size changes), LRU by bytes under `STACKS_RENDER_MAX` (default 6G) down to 90%, and a cache tenant (`render`, one entry per document), so they count toward `STACKS_CACHE_MAX` and leave in LRU order with everything else. A failed page or document is not tried again for 10 minutes. Local-lane files (`/local/…`) are not rendered.
- `server/routes/16-render.mjs`: `GET /render/page?u=&k=&w=[&lane=fg|near][&wait=ms]` (200 the JPEG with `X-Render: {n, pw, ph, w, ms, by}`, `ETag`, `Access-Control-Allow-Origin: *` and `Access-Control-Expose-Headers: X-Render`; rendered at `fg` when missing, waiting up to `wait`, default 1500, at most 5000 ms; 204 no engine, still starting or the PDF not on disk yet (`X-Render-Why`), 202 not ready in time, 403 off the allowlist, 404 no such page, 422 the engines failed: all at once, never a slow error), `POST /render/hint {open: {u, k, w, n?, per?}, next: [{u, k}]}` (→ `{seq, engine, n: {url: pages}}`), `GET /render/state` (`{engine, pending, workers, classes}`) and `?u=&w=` (`{n, w, bits, ready, running, queued, src}`; computes the page count of a PDF on disk), `POST /render/forget {u}`, and `render` in `/status` (engine and engines, queues, `done`, `failed`, `dropped`, `hits`, engine ms `p50`/`p90`, `bytes`, `max`, the self-test `report`).
- Client: `render.js` asks `GET /render/state` at load (again every 2 s while `pending`) and sets `serverRender.on`; for a web PDF page without a stored display image, `renderPage(it, k, {lane})` asks `GET /render/page` from the second origin (`util.js` `SHARD`), decodes the Blob with `createImageBitmap` and crops it as scans are (`cropOf` with a profile, else `analyze(bitmap, {scan: false})`), panels `src: 'server'`; the reader waits at most 700 ms, prefetch (`lane: 'near'`, at most 2 requests at once) 2.5 s; anything else falls back to pdf.js. After two foreground pages too slow in a row, for 20 s foreground requests only check readiness (`wait=0`). A foreground call for a page a prefetch request is still waiting on asks again at `fg` and the prefetch takes its result. `X-Render`'s `n` sets `it.n`, and `serverCount(it)` asks `/render/state`, so a PDF need not be parsed with pdf.js to be shown; pdf.js still opens lazily for the text layer, outline, figure peek and read-aloud. `prefetch.js` `sendHint()` (from `planAround`, debounced 150 ms): the open PDF and the next 12 web PDFs in `state.order` with `startOf()`; the reply's page counts set `it.n`; `planAround` prepares at `lane: 'near'` and, for the next PDFs not yet opened, uses `serverCount` before falling back to `openDoc`.
- Settings: `STACKS_RENDER_ENGINE`, `STACKS_RENDER_WORKERS`, `STACKS_RENDER_MAX`.
- Tests: `node --test test/render-engine.test.mjs test/render-queue.test.mjs test/render-api.test.mjs` (engines and the self-test against the geometry PDF, falling through, lanes and caps with a stand-in engine, plan replacement, the LRU cap, the routes against a server with `STACKS_RENDER_ENGINE=poppler` and `none`); `node test/render-bench.mjs --on N --off M` (Playwright: two running servers on the same PDFs, one with `STACKS_RENDER_ENGINE=none`, interleaved: first spread, turns, hops, and text-layer words over server pages against pdf.js pages).

## Learning from reading

Reading memory becomes a learned profile that reweights For you, sinks what you finished or skipped, and tilts the lane mix in All. The build spec, with every formula and number: `docs/learning/spec.md` (sections 2-6).

- `server/learn.mjs` is pure (no `fs`, no timers; tests import it): `engagement(it, r)` turns a memory record into an engagement `y` (0-1: active time against the item's expected time, pages read at reading pace, return days) and a weight `w` (quick exits weigh less, by how the visit ended and how it was reached; load failures and glimpses are not exposures); `replay(jl)` replays judgments including Back's retractions (`unsave`, `unmore`, `unless`); `buildIndex(items, {tags, meta, lanes})` gives every item its features (tags, meta field paths, library folders, first author, lane, title words, style, level, form, era) with group weights; `computeProfile(...)` gives each feature a shrunk interest weight λ (log2 of its mean engagement against yours, clipped to ±2), applies the reader's boost / mute / ignore, and predicts every item's interest `I = tanh(r/0.75)`. The feed's term is `0.8·I + Φ`, where Φ (−0.8 … +0.3) sinks done, skipped and glanced items, lifts items in progress, and gives new finds +0.3 fading over 14 days. Lanes get a factor `2^(0.6·λ_lane)` (0.44-2.30). Also `explainItem` (chips whose shares add up to `0.8·I`), `findState` (new, seen, kept, dismissed), seeds for jobs, and a Spearman calibration check. `LEARN` holds every constant; bump `GEN` when a formula changes.
- `server/routes/45-memory.mjs` sets `app.memory = {index, take(ops), subscribe(fn)}`. Visit rows carry how a visit ended (`x`: next, prev, less, more, jump, lane, view) and how it was reached (`via`: feed or jump); `brief()` and the CSV replay judgments.
- `server/routes/47-learn.mjs`, the profile service: builds the index in 2,000-item chunks at start, recomputes 250 ms after a judgment or control change, 10 s after reading ops (at most 60 s after the first), when `corpus.json`, `data/meta.json` or `data/tags.json` change (checked every 30 s), every 6 h and after midnight. One recompute at a time; about 20-30 ms on the current corpus. Routes: `GET /learn/profile.json?part=rank[&since=at]` (pre-serialized, what the feed needs: `pred`, `phi`, `lanes`, `laneFactor`, `new`), `GET /learn/profile.json` (full, for the Dashboard), `GET /learn/why?id= | ?ids=`, `GET /learn/features?q=`, `GET /learn/history.json`, `GET /learn/reading.json`, `GET /learn/finds.json`, `POST /learn/control`, `POST /learn/import` (the one-time `state.aff` migration), `POST /learn/finds/mark`; `learn` and `corpusAt` in `/status`. Other routes read `app.learn` (`profile`, `index`, `items`, `onCorpus(fn)`, `onUpdate(fn)`). Its files, under `CACHE/learn/` only: `profile.json`, `history.jsonl`, `opens.jsonl` (the calibration data), `controls.json`, `finds.json`, `import.json`. `STACKS_LEARN=0` turns it off.
- Client: `features/learn.js` (the score term and lane factor through the hooks above, why lines, NEW badges, the NEW chip and the New walk, Keep and Dismiss), `features/dashboard.js` (`Y`: new items, reading, what it learned, how ranking moved, open and done jobs) and `features/flag.js` (`!`: flag an item for an agent).
- Tests: `node --test test/learn-core.test.mjs test/learn-sim.test.mjs test/learn-api.test.mjs` (`test/learn-ops.mjs` makes synthetic reading as memory ops).

## Finding new material: agent jobs, not an in-app crawler

The app does not search the web for new material itself. It learns from your reading (the learned profile reweights the "For you" ranking) and turns that, plus the library's own gaps (items that fail to open, blocked images, untagged items, problems you flag), into **open jobs**: one Markdown file per job in `jobs/open/`. An outside agent, such as Claude Code pointed at this repository, picks them up by following `jobs/README.md`, edits the data files directly, checks its work with `node jobs.mjs check <id>`, and closes the job (`jobs/done/`). Items an agent adds carry provenance (`added`, `job`, `via`, `why`) and a NEW badge until read. Job files never contain reading history: the repository is public. Design and build notes: `docs/learning/spec.md` (section 7; it replaces an earlier plan for in-app discovery).

- `server/jobs.mjs` (shared by the server and the CLI): the job file format (`parseJob`, `formatJob`: YAML frontmatter with one `key: <JSON>` per line, then a Markdown body), ids (`nextId`, written with `wx`), the generator (`candidates`, `refresh`: nine types, `discover`, `follow-author`, `grow-lane`, `fix-item`, `media`, `tag`, `metadata`, `thread` and `flag`, deduped by key, capped at 30 open, with cool-downs; untouched maintenance jobs may gain inputs), `privacyLint` (masks public titles, ids and names, then rejects anything that reads like reading history), the checker (`checkJob`: counts, item rules, duplicates by every key, open hosts from `jobs/hosts.json`, scans, the merge, `--live` URL checks), `doneJob`, `dropJob`, `dismissJob` and `applyMediaFixes`.
- `server/routes/96-jobs.mjs`: `GET /jobs`, `POST /jobs/refresh`, `POST /jobs/flag`, `POST /jobs/dismiss`, `POST /jobs/report` (open errors the reader's browser saw, into `CACHE/jobs/errors.json`), `GET /jobs/asset`; `jobs` in `/status`. It refreshes 2 minutes after start when the last refresh is older than `STACKS_JOBS_EVERY` hours (24; 0 = only on request), then checks hourly; a new cache counts from its first start (`state.since`), so a server on a fresh cache writes no job files for a day; applies `data/media-fixes.json` through `rescue.mjs` `manualCopy`; and adds new items' hosts to `app.cache.ALLOW` when the corpus changes. `STACKS_JOBS_DIR` moves the jobs folder (tests and dev servers: set it, or a dev server writes real job files into the repository); `STACKS_JOBS_MAX` the cap. Its own state lives in `CACHE/jobs/state.json`.
- `jobs.mjs` (the agent's CLI): `list`, `next`, `show`, `lookup`, `check [--live]`, `done`, `drop`, `new`, `skeleton`. `build-corpus.mjs --merge [--root DIR]` folds lane-file items (`data/lanes/<lane>.added.json`) and `data/overrides.json` into `corpus.json` without network in about a second (the curated lane files only with `--all-lanes`; links on deny-listed hosts never); the full build applies the overrides too.
- Repository files agents edit: `data/lanes/*.added.json`, `data/overrides.json`, `data/media-fixes.json`, `data/tags.json`, `data/threads.json`, `jobs/hosts.json` (open hosts with reasons, and the shadow-library deny list).
- Tests: `node --test test/jobs-core.test.mjs test/jobs-check.test.mjs test/jobs-merge.test.mjs test/jobs-api.test.mjs test/jobs-adversarial.test.mjs` (the last: additions `check` must refuse, found in QA); every test writes jobs to a temp `STACKS_JOBS_DIR`.
